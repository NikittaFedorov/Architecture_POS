# ПОС

Консольное приложение для преподавательского оценивания студентов по общему рубрикатору. Каждая оценка связана с преподавателем, студентом и критерием. Отчеты можно группировать по студентам, преподавателям или критериям и выгружать в JSON и TXT с возможностью расширения поддерживаемых форматов. Данные хранятся в SQLite или DuckDB в зависимости от варианта сборки с возможностью расширения поддерживаемых баз данных.

## Функциональные требования

- Регистрировать студентов и преподавателей и просматривать сведения о них. При регистрации преподавателя можно задать его вес в расчете.
- Добавлять критерии оценивания и просматривать рубрикатор. Для каждого критерия указываются название, максимальный балл и вес.
- Выставлять, просматривать, исправлять и отменять оценки. При просмотре оценки видны автор, критерий и балл.
- Формировать отчеты с фильтрами по студентам, преподавателям и критериям. Поддерживаются группировка по любому из этих признаков, вывод в консоль и выгрузка в JSON и TXT.

## Правила оценивания

Оценка относится к зарегистрированному студенту, зарегистрированному преподавателю и критерию из рубрикатора. Для каждой такой тройки допускается одна текущая оценка. Повторное выставление отклоняется.

Вес преподавателя - положительное число. По умолчанию вес равен 1. Он определяет вклад оценок преподавателя в средний балл по критерию при взвешенном расчете.

Максимум и вес критерия строго положительны. Их значения фиксируются при добавлении критерия. Балл задается с точностью до десятых и должен находиться в пределах от нуля до максимума критерия включительно. При недопустимом исправлении сохраняется прежний балл. Отмена удаляет оценку из базы, поэтому она исключается из последующих расчетов.

Выбранные в консоли преподаватель и студент задают ограничения для операций с оценками и построения отчетов. Выбор преподавателя - режим работы консоли.

## Отчет

Команда `report` принимает фильтры `student`, `teacher` и `criterion`. Внутри одного фильтра можно выбрать несколько значений. В отчет попадают оценки, которые удовлетворяют всем заданным фильтрам. По умолчанию используются `group student` и `average simple`.

| Группировка | Порядок групп | Веса для `average weighted` |
|---|---|---|
| `group student` | Студент - критерий - преподаватель | Веса преподавателей внутри критерия, затем веса критериев внутри студента. |
| `group teacher` | Преподаватель - студент - критерий | Для итога каждого студента используются веса критериев, затем результаты студентов усредняются с равным весом. |
| `group criterion` | Критерий - преподаватель - студент | Студенты имеют вес 1. Для итога по критерию используются веса преподавателей. |



## DDD

### Единый язык

| Термин | Имя в модели | Значение | Роль в DDD |
|---|---|---|---|
| Студент | `Student` | Участник, которого оценивают. | Entity |
| Преподаватель | `Teacher` | Участник, который выставляет оценки. У него есть вес для расчета среднего балла. | Entity |
| Рубрикатор | Коллекция `Criterion`, доступная через `IRubricRepository` | Общий набор действующих критериев. | Коллекция сущностей |
| Критерий | `Criterion` | То, за что выставляется балл. Задает максимум и вес. | Entity |
| Балл | `Score` | Неизменяемое числовое значение балла, выставленного по критерию. | Value Object |
| Оценка | `Evaluation` | Балл, который преподаватель поставил студенту по конкретному критерию. | Сущность |
| Калькулятор результата | `ResultCalculator` | Рассчитывает статистику и взвешенный итог. | Domain Service |
| Отчет | `AssessmentReport` | Группы оценок, отобранные участники, критерии и рассчитанная статистика. | Модель для чтения |

**Балл - объект-значение.** `Score` хранит неотрицательное число типа `decimal` с точностью до десятых. `Evaluation` проверяет, что балл укладывается в максимум критерия.

Для одного студента, преподавателя и критерия существует максимум одна оценка. `EvaluationKey` хранит номера всех троих, по которым репозиторий находит запись. При исправлении `AssessmentSession` проверяет, что запись существует, и создает `Evaluation` с новым баллом для проверки максимума критерия. Затем репозиторий обновляет балл в найденной записи.

**Калькулятор отчетов - - доменный сервис.** `AssessmentReportBuilder` задает порядок полей, допустимые значения и веса. `ResultCalculator` фильтрует строки, строит вложенные группы и усредняет значения снизу вверх. В калькулятор передаются функции чтения полей, балла и его доли от максимума. Он работает с любыми строками, для которых заданы эти функции.

### Репозитории

В приложении четыре объекта-репозитория с отдельными интерфейсами. Все четыре используют одну БД.

| Интерфейс | Операции |
|---|---|
| `IStudentRepository` | Добавить студента, найти студента, получить список студентов. |
| `ITeacherRepository` | Добавить преподавателя с его весом, найти преподавателя, получить список преподавателей и их веса. |
| `IRubricRepository` | Получить действующий рубрикатор, найти и сохранить критерий. |
| `IEvaluationRepository` | Найти, добавить, обновить или удалить балл по `EvaluationKey`. Вернуть строки для просмотра оценок и формирования отчета. |

Уникальность тройки обеспечивается ограничением `UNIQUE` в базе. При попытке повторного добавления репозиторий возвращает признак конфликта, по которому приложение сообщает, что оценка уже выставлена.

## Паттерны GoF

| Группа | Паттерн | Применение |
|---|---|---|
| Порождающий | **Builder** | `AssessmentReportBuilder` поэтапно принимает фильтры, способ усреднения и группировку. Затем `Build()` читает данные, рассчитывает статистику и возвращает готовый `AssessmentReport`. |
| Структурный | **Facade** | `RelationalDatabase` предоставляет SQL-репозиториям метод `Query`: запрос, параметры и функция чтения строки. Он скрывает создание и освобождение `DbCommand`, создание `DbParameter`, выполнение запроса и обход `DbDataReader`. |
| Поведенческий | **Command** | Реализации `ConsoleCommand`, например `SetScoreConsoleCommand`, инкапсулируют действия CLI. `CommandDispatcher` находит команду по имени и вызывает `Execute`. |
| Поведенческий | **Strategy** | `AssessmentReportBuilder` передает `ResultCalculator` одну из двух реализаций `IAverageStrategy`: `SimpleAverage` или `WeightedAverageStrategy`. Та же стратегия усредняет значения и доли от максимума на каждом уровне группировки. |

`AssessmentSession` играет роль прикладного фасада для консольных команд. Через нее команды выполняют операции с оценками, меняют режим и создают построитель отчета. Часть операций доступна командам через вложенный базовый класс `ConsoleCommand`.

## SOLID

- **SRP - единственная ответственность.** `Score` проверяет допустимость числового значения, `Evaluation` проверяет максимум критерия, `ResultCalculator` рассчитывает статистику, а экспортеры оформляют готовый отчет. `AssessmentSession` совмещает прикладные операции и хранение выбранного режима. Это место, где ответственность разделена менее строго.
- **OCP - открытость к расширению.** Новый формат экспорта подключается реализацией `IReportExporter` и регистрацией в `Program.cs`. `ExportReportCommand` получает форматы из зарегистрированных реализаций. Для новой SQL-базы подключаются драйвер и схема, а ее реализация `RelationalDatabase` выбирается при сборке. Сессия и команды продолжают работать через интерфейсы репозиториев. Для нового режима усреднения понадобится реализация `IAverageStrategy`, а также изменения в разборе аргументов и выборе стратегии в `AssessmentReportBuilder`. Навигация предполагает возможность дальнейшего расширения вариантов работы программы, например, добавление GUI слоя.
- **LSP - принцип подстановки Лисков.** `SimpleAverage` и `WeightedAverageStrategy` принимают один и тот же набор значений с весами. Обе возвращают среднее в шкале входных значений, поэтому `ResultCalculator` может подставить любую из них и для баллов, и для долей от максимума. `ExportReportCommand` передает каждому экспортеру готовый отчет и поток, который остается открытым после записи.
- **ISP - разделение интерфейсов.** `IAverageStrategy` предоставляет только расчет среднего, а `IReportExporter` - имя формата и запись готового отчета. Так калькулятор зависит только от операции усреднения, а команда выгрузки - от операций экспорта. Интерфейсы репозиториев разделены по видам данных. В `IEvaluationRepository` совмещены запись оценок и чтение данных для отчетов.
- **DIP - инверсия зависимостей.** `AssessmentSession` получает четыре интерфейса репозиториев через конструктор. SQL-реализации подключаются при запуске. `ExportReportCommand` получает реализации `IReportExporter`, а JSON- и TXT-экспортеры находятся в инфраструктуре.

## Внедрение зависимостей

При запуске `Program.cs` передаёт в `AssessmentCli.Run` функцию, которая настраивает хранилище и экспорт отчётов. `Run` создаёт коллекцию `services`, вызывает эту функцию и добавляет регистрации консольной части. Затем DI-контейнер по этим правилам создаёт объекты и передаёт их друг другу через конструкторы.

| Где регистрируется | Что регистрируется | Кто получает эти объекты и зачем |
|---|---|---|
| `AssessmentCli.Run` в `CLI/AssessmentCli.cs` | `ConsoleLoop`, `CommandDispatcher`, `ConsoleMode`, `AssessmentSession`. Команды регистрируются под общим типом `ConsoleCommand`, а `HelpCommand` и `ExitCommand` - отдельно. | `ConsoleLoop` получает `CommandDispatcher` для вызова команд, `ConsoleMode` для вывода приглашения и `ExitCommand` для завершения сеанса.<br>`CommandDispatcher` получает `IEnumerable<ConsoleCommand>`, `HelpCommand` и тот же экземпляр `ExitCommand`. Для вывода справки `HelpCommand` получает `IEnumerable<ConsoleCommand>` и `ExitCommand`.<br>`ConsoleMode` и прикладные команды получают `AssessmentSession` из `Application`. В ней хранится текущий выбор преподавателя и студента. |
| `RelationalStorageServices.AddRelationalStorage` в `Infrastructure/Relational` | `IStudentRepository` -- `SqlStudentRepository`<br>`ITeacherRepository` -- `SqlTeacherRepository`<br>`IRubricRepository` -- `SqlRubricRepository`<br>`IEvaluationRepository` -- `SqlEvaluationRepository` | `AssessmentSession` получает репозитории через интерфейсы из `Core/Repositories.cs` и через них читает и сохраняет данные. SQL-реализации находятся в `Infrastructure/Relational`. |
| `RelationalStorageServices.AddRelationalStorage`, функция открытия базы передаётся из `Program.cs` | `RelationalDatabase` -- `SqliteDatabase` или `DuckDbDatabase` | Все четыре SQL-репозитория получают `RelationalDatabase` через конструкторы и выполняют через него запросы. Реализация базы выбирается при сборке приложения. |
| `Program.cs` | `IReportExporter` -- `JsonReportExporter` и `TextReportExporter` из `Infrastructure/Export`. Интерфейс находится в `Core/Reports`. | `ExportReportCommand` получает обе реализации через `IEnumerable<IReportExporter>`, выбирает экспортёр по аргументу `json` или `txt` и передаёт ему готовый отчёт. |

Например, `AddScoped<IStudentRepository, SqlStudentRepository>()` говорит контейнеру подставить `SqlStudentRepository` в параметр конструктора типа `IStudentRepository`. В конструкторе самого репозитория нужен `RelationalDatabase`. Для него зарегистрирована функция `() => new AssessmentDatabase(databasePath)`. Контейнер вызывает её, когда ему впервые нужно подключение.

`Run` создаёт одну область DI на весь консольный сеанс и запрашивает в ней `ConsoleLoop`. Контейнер собирает зависимости цикла до начала чтения команд. Регистрации `Scoped` дают по одному экземпляру на область, поэтому команды разделяют сессию, а репозитории - подключение. По завершении сеанса `Run` освобождает область, и подключение закрывается. Экспортёры зарегистрированы как `Singleton`, поэтому контейнер создаёт по одному экземпляру каждого формата на всё время своей работы. По сути по времени жизни они сейчас совпадают с `Scoped`, так как область у DI сейчас одна.
