# ПОС

Консольное приложение для преподавательского оценивания студентов по общему рубрикатору. Каждый преподаватель выставляет собственные оценки. Отчет по студенту можно получить по всем преподавателям или по одному выбранному.

## Функциональные требования

- Регистрировать студентов и преподавателей и просматривать сведения о них. При регистрации преподавателя можно задать его вес в расчете.
- Добавлять критерии оценивания и просматривать рубрикатор. Для каждого критерия указываются название, максимальный балл и вес.
- Выставлять, просматривать, исправлять и отменять оценки. При просмотре оценки видны автор, критерий и балл.
- Формировать отчет по студенту. Для отчета по всем преподавателям пользователь выбирает обычное среднее или среднее с учетом весов преподавателей. Готовый отчет можно выгрузить в выбранном поддерживаемом формате. Конкретный набор форматов определяется при реализации.

## Правила оценивания

Оценка относится к зарегистрированному студенту, зарегистрированному преподавателю и критерию из рубрикатора. Для каждой такой тройки допускается одна текущая оценка. Повторное выставление отклоняется.

Вес преподавателя - положительное число. По умолчанию вес равен 1. Он определяет вклад оценок преподавателя в средний балл по критерию при взвешенном расчете.

Максимум и вес критерия строго положительны. Их значения фиксируются при добавлении критерия. Балл может быть дробным и должен находиться в пределах от нуля до максимума критерия включительно. При недопустимом исправлении сохраняется прежний балл. Отмена исключает оценку из последующих расчетов.

## Отчет

Отчет строится по текущим оценкам студента. В нем указано, чьи оценки вошли в расчет, а для сводки по всем преподавателям - какой способ усреднения выбран. Эти сведения сохраняются при выгрузке.

Для каждого критерия рассчитывается средний балл одним из двух способов:

- **Обычное среднее.** Сумма выставленных баллов делится на число преподавателей, выставивших оценку по этому критерию.
- **Среднее с учетом весов преподавателей.** Каждый выставленный балл умножается на вес его автора. Сумма этих произведений делится на сумму весов преподавателей, выставивших оценку по этому критерию.

В отчете по одному преподавателю средний балл по критерию равен его оценке. В обоих способах отчет также показывает наименьший и наибольший выставленные баллы, максимально допустимый балл и количество преподавателей, выставивших оценку. Для критерия без оценок количество равно нулю, а статистика по баллам отсутствует. Выставленный ноль участвует в расчете.

В отчет входит взвешенный итог. Среднее по каждому оцененному критерию делится на максимум этого критерия и умножается на вес критерия. Сумма полученных вкладов делится на сумму весов оцененных критериев. Рядом с итогом указывается "оценено N из M критериев". Если оцененных критериев нет, итог отсутствует.

## DDD

### Единый язык

| Термин | Имя в модели | Значение | Роль в DDD |
|---|---|---|---|
| Студент | `Student` | Участник, которого оценивают. | Entity |
| Преподаватель | `Teacher` | Участник, который выставляет оценки. У него есть вес для расчета среднего балла. | Entity |
| Рубрикатор | `Rubric` | Общий набор действующих критериев. | Коллекция сущностей |
| Критерий | `Criterion` | То, за что выставляется балл. Задает максимум и вес. | Entity |
| Балл | `Score` | Неизменяемое числовое значение балла, выставленного по критерию. | Value Object |
| Оценка | `Evaluation` | Запись о том, кто, кому, по какому критерию и сколько баллов поставил. | Entity, Aggregate Root |
| Калькулятор результата | `ResultCalculator` | Рассчитывает статистику и взвешенный итог. | Domain Service |
| Отчет | `AssessmentReport` | Результаты студента с указанием, чьи оценки учтены и как рассчитан средний балл в сводке. | Представление для чтения |

**Балл - объект-значение.** `Score` хранит неотрицательное число типа `decimal`. Два балла равны, если равны их числа. Допустимость балла по максимуму критерия проверяет оценка.

**Агрегат оценки** состоит из одной `Evaluation` и ее балла `Score`. При исправлении приложение находит оценку по студенту, преподавателю и критерию, затем читает максимально допустимый балл по этому критерию. `Evaluation` проверяет новое значение и заменяет балл, если он допустим.

**Калькулятор - доменный сервис.** Он получает рубрикатор, оценки студента и веса их авторов. Выбранная стратегия вычисляет средний балл по каждому оцененному критерию. Калькулятор рассчитывает взвешенный итог по средним баллам и весам критериев. Консоль и экспортер получают результат одного и того же расчета.

### Репозитории

В приложении четыре объекта-репозитория с отдельными интерфейсами. Все четыре используют одну БД.

| Интерфейс | Операции |
|---|---|
| `IStudentRepository` | Добавить студента, найти студента, получить список студентов. |
| `ITeacherRepository` | Добавить преподавателя с его весом, найти преподавателя, получить список преподавателей и их веса. |
| `IRubricRepository` | Получить действующий рубрикатор, найти и сохранить критерий. |
| `IEvaluationRepository` | Найти оценку по студенту, критерию и преподавателю, добавлять, сохранять и удалять оценки. Получить оценки студента для отчета с возможностью отбора по преподавателю. |

Репозиторий оценок обеспечивает уникальность тройки при добавлении.

## Паттерны GoF

| Группа | Паттерн | Применение |
|---|---|---|
| Порождающий | **Builder** | Отчет собирается поэтапно. В него добавляются способ расчета и результаты по критериям, затем взвешенный итог и количество оцененных критериев. После сборки получается готовый отчет для консоли или выгрузки. |
| Структурный | **Facade** | Через консоль вызываются операции приложения через фасад |
| Поведенческий | **Command** | Выставление, исправление и отмена представлены командами с входными данными. Обработчик каждой команды выполняет соответствующую операцию с оценкой. |
| Поведенческий | **Strategy** | Прикладной сценарий выбирает обычное или взвешенное среднее и передает соответствующий объект стратегии при создании `ResultCalculator` для отчета. Калькулятор выступает контекстом и поручает стратегии вычислить средний балл по каждому оцененному критерию. У обеих стратегий общий интерфейс. |

У каждого поддерживаемого формата своя реализация `IReportExporter`. Операция выгрузки передает готовый отчет одному экспортеру выбранного формата.

## SOLID

- **SRP - единственная ответственность.** `Evaluation` управляет баллом конкретной оценки. При исправлении она принимает новый балл, если он находится между нулем и максимумом критерия. `ResultCalculator` рассчитывает статистику и итог для отчета. Экспортер записывает готовый отчет в своем формате.
- **OCP - открытость к расширению.** Новый способ усреднения подключается как реализация интерфейса стратегии, а новый формат выгрузки - как реализация `IReportExporter`. При добавлении варианта обновляется список доступных реализаций. Калькулятор и операция выгрузки обращаются к ним через существующие интерфейсы.
- **LSP - принцип подстановки Лисков.** Взаимозаменяемость определяется поведением, которое обещает интерфейс. Стратегии усреднения принимают одинаковые входные данные и возвращают средний балл по критерию. Экспортеры записывают готовый отчет в разных форматах. 
- **ISP - разделение интерфейсов.** Для добавления критерия достаточно `IRubricRepository` с операциями чтения рубрикатора и сохранения критерия. Для записи готового отчета используется `IReportExporter`. Работа со студентами, преподавателями и оценками выделена в собственные интерфейсы.
- **DIP - инверсия зависимостей.**
